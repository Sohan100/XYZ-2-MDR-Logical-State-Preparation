Data Layout Guide
=================

The `data/` folder stores generated artifacts only. Source code and workflow
logic should continue to live under `src/`, `scripts/`, and `slurm/`.

Top-level folders
-----------------

- `tables/`
  Canonical MDR table CSVs grouped by code family, for example
  `tables/xyz2/` and `tables/surface/`.
- `simulation_results/`
  Saved sweep CSVs and spec sidecars grouped by code family.
- `plots/`
  Rendered figures grouped first by code family or workflow origin.
- `analysis/`
  Saved report-oriented CSV outputs used by notebooks and offline analysis.

Current organization conventions
--------------------------------

- Family-specific artifacts should live under a code-family subdirectory
  whenever that makes sense.
- Threshold plots generated by `scripts/plot_thresholds_from_csv.py` are
  stored under `plots/<code_family>/thresholds/`.
- Notebook-generated threshold plots live under
  `plots/analysis_notebook/<code_family>/thresholds/`.
- Historical one-off or legacy plot outputs should be kept in clearly named
  subfolders such as `legacy_cli/` or `comparisons/` instead of the top level
  of `plots/`.

Notes
-----

- Some older `xyz2` analysis CSVs remain directly under `analysis/xyz2/`
  because the current notebook expects those filenames there.
- Empty `surface/` folders are present in places where the repository now has
  a family-aware layout, even if no artifacts have been generated there yet.
